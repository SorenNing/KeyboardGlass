# KeyboardGlass 0.2.3

Target: iOS 16.0+ (iOS 16/17), normal rootless arm64 and RootHide arm64e. Author: Ning. Runtime validation on iOS 16 devices is pending; SDK/API and package compatibility are checked separately.

System Settings → 键盘玻璃 provides the current original material plus six procedural presets: clear, frost, crystal, ice, smoke and liquid. Manually adjusted values are shared across presets and survive skin changes; untouched fields follow the selected preset. On upgrade, Settings migrates explicit adjustments from the previously active skin into the shared `Overrides["*"]` entry, preserving the legacy entries as inactive backups. An empty shared entry deliberately takes precedence over those backups. Seventeen sliders (including independent background blur strength) control system backdrop alpha, body RGB, opacity and brightness, gradient strength/direction, highlight thickness/brightness/width, inner/outer shadow, edge softness, corner radius and superellipse corner shape. Each slider has a separate visible group title. Restore-material clears the shared manual adjustments and uses the current skin preset, keeping system alpha and the candidate-controls switch. Restore-all restores original material, system alpha 1.0, and the switch off.

An optional `隐藏候选栏收起按钮` switch defaults to off. When enabled, narrowly scoped candidate/arrow layout hooks hide the arrow's direct image view and vertical candidate separator, and disable the invisible arrow hit target without reclaiming its layout slot. Background layers and candidate labels remain unchanged. Switching off restores the recorded native hidden/interaction state; each native layout runs after restoration before reapplying the option. The option is global across skins and shared snapshots; legacy snapshots omit it and therefore keep it off. Restore-all clears it, while restore-current-skin leaves it unchanged. Actual glyph/line appearance and candidate expansion interactions remain pending device testing.

The old background-effect overlay and animator have been deleted. Optional material blur (default off) processes only the generated or original premultiplied RGBA glass image with a separable Gaussian filter. The result replaces the image in the same existing UIImageView, with the original scale, cap insets and transparent silhouette preserved. It adds no view, layer or backdrop sampler. `MaterialBlurStrength` is 0–1 (default 0.5), corresponding to sigma 0–4pt on the source image. It softens the material texture, highlights and shadows; it does not blur the App content behind it. Keys and labels remain unchanged. New keys deliberately do not reuse the rejected overlay's saved enable flag. The system background opacity and opaque outline mask are independent.

Version 0.2.3 fixes two material-edge issues. Outer-shadow strength no longer moves the body or its mask inward by 6pt; shadows are clipped to the existing corner cutout without changing layout. Material and outline share `GlassRaster.h`, a normalized superellipse boundary/normal and centered coverage function. The 128pt stretch tile is generated at 3x with 2x2 subpixel integration. Highlight/gradient direction follows boundary normals so straight edges stay constant across cap/stretch joins. Mask bounds now match the native backdrop's local origin explicitly. Numerical checks cover all supported radii/shapes, shadow-independent contour position, premultiplied alpha and cap continuity. Actual smoothness and alignment on the user's keyboard remain to be verified after installation. User preferences and skin IDs are preserved.

`GlassPreferences.h` is the shared settings model with finite-number validation and bounds. `GlassRenderer.h` creates a cached premultiplied RGBA stretchable material on the main thread. Variable corners and edge features stay inside the fixed cap areas. Outer shadows fit within the existing keyboard clipping, without expanding layout. The untouched original PNG remains the default until the original skin is customized. No image files, screenshots, remote capture, Metal, or background sampling are used.

The existing keyboard layout hook, connected-region seam alignment, and original-layout-first behavior remain. Settings writes canonical values through CFPreferences, then atomically publishes a schema-validated snapshot to `/var/mobile/Library/Accessibility/KeyboardGlass-preferences.plist`. Each App reads that shared snapshot rather than its sandbox preference domain. Snapshot publication success/failure is recorded in Settings' Caches/KeyboardGlass-settings-sync.log. A Darwin notification, becoming active, keyboard presentation, and throttled layout reads refresh the snapshot. A corrupt/unreadable update retains the last good configuration. Each host logs its effective skin/alpha/radius/source. For sandboxed App hosts, a failed file read triggers a throttled libSandy profile request and an immediate retry. The RootHide profile permits every host signing identifier (`*`) to request read-only access to this exact configuration file; it uses `/rootfs/var/mobile/Library/Accessibility/KeyboardGlass-preferences.plist` so RootHide sandyd issues access to the real host path. It never grants directory or App-data access. The installed libSandy is resolved from the injected library's active root; `com.opa334.libsandy` is a package dependency. Diagnostics include profile return code and file-read error, falling back to each App's Caches directory when the global log is not writable. Success requires a readable and validated snapshot, not just profile return code zero. Actual third-party App authorization and refresh after Settings atomically replaces the file still require device verification. System backdrop alpha defaults to 1.0 independently of skin opacity.

Settings mirrors framework `setSpecifiers:` invalidations into its local cache. On visible foreground resume, it rebuilds the inherited specifier state, reloads the table and restores a clamped scroll offset without resetting saved preferences. The cache regression uses the production setter/getter/rebuild implementation with a Foundation stand-in and repeated simulated invalidation/resume cycles; UIKit foreground behavior still needs device verification.

Builds are manual GitHub Actions on macos-latest, producing both normal rootless arm64 (subtype 0, var/jb payload, non-/rootfs libSandy target) and RootHide arm64e (subtype 0x80000002, Library payload, /rootfs libSandy target). Native Xcode compiles both executables with an iOS16 deployment target and verifies the minimum-OS commands and strict signatures again after extracting them from the final packages. Package firmware dependency is >=16.0. Backdrop and candidate hooks retry when the keyboard is shown, each with its own install-once guard and original function pointer. Missing classes/signatures are skipped rather than guessed. The Preferences bundle resolves the already-loaded private Preferences framework at runtime. The source carries its own narrow declarations instead of an SDK-private framework dependency.

Local strict arm64e syntax validation is not an on-device Settings/UI test. Confirm row visibility, parameter persistence across Apps, skin switching, reset actions, keyboard clipping and visual results after installation. These are static material controls; they do not implement real-time refraction. Stable 0.1.0 and the 0.1.10 alpha0.9 package remain separate saved releases.
